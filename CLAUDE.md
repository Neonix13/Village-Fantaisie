# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A French-language hidden-role party game ("loup-garou"-style) meant to run alongside a real house party over several hours. Phones are passed around to draw roles; the shared "Village" screen sits in the middle of the room; each player briefly opens a private "espace secret" to see their role and use their power. **Two ways to play, same UI:**

- **One shared phone** (static site on GitHub Pages, or any page not served by the host server): the game lives in that phone's `localStorage`.
- **Several phones on ONE game** (server run by the host's laptop, `npm start` / `npm run public`): the laptop holds the game and every connected phone sees and does the same thing on it. Phones do not need to be on the same wifi if the laptop is exposed through a tunnel (see Commands).

Constraints from the user: no third-party online game server (no Firebase & co), and later the host is meant to move to *the phone of the person who creates the game* (see "Future" below). There used to be an older multi-device implementation (per-player links, admin dashboard, SQLite); it was deleted on purpose. Don't reintroduce a database or per-player URLs — the only server persistence is the `partie.json` snapshot.

**`master` is the web-only version**: the PC runs `server.js` and phones open the page (over the local wifi or a tunnel). The Android/Capacitor app, PWA files, Play Store visuals and privacy policy live only on the **`appli-mobile`** branch (a revert of that work sits on `master`; re-merging it means reverting the revert). `.gitignore` on `master` blocks `android/`, `www/` and signing keys so they can never be committed here.

## Commands

```bash
npm install       # express, ejs, ws, qrcode — no native build step
npm start         # or: node server.js — serves on :3000, one game shared by all connected phones
npm run public    # same + Cloudflare quick tunnel (needs cloudflared) so phones on any network can join
```

On Windows PowerShell, if `npm start` fails with an execution-policy error, use `npm.cmd start` (or `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once).

There is no committed test suite, linter, or build step. Check syntax with `node --check public/jeu.js public/game.js public/net.js server.js`. No browser is available to Claude Code here, so UI changes have only been verified by running `jeu.js` in a `vm` context against a stubbed `document` (fake `getElementById`/`localStorage`, capture the `click` listener registered on `#app`, then call it with `{ target: { closest: () => ({ getAttribute: k => ... }) } }`) — that pattern works well for exercising whole flows. Visual fidelity has to be checked by the user on a phone.

**Giving the address to players**: open `http://localhost:3000/hote` on the laptop — it lists every reachable address with a QR code, how many phones are connected, and a "Nouvelle partie" button. The LAN IP changes when the wifi reconnects, so re-read that page rather than remembering it. `/hote*` requests carrying proxy headers (`X-Forwarded-For`, `Cf-Connecting-Ip`) get a 403, so players coming through the tunnel can't open them.

**Playing across different networks**: `npm run public` spawns `cloudflared tunnel --url http://localhost:3000` (install once: `winget install --id Cloudflare.cloudflared`) and shows the `https://…trycloudflare.com` address on `/hote`; it changes at every launch. Cloudflare only relays traffic (nothing stored) but it is a third party in the path. The tunnel itself has **not been tested** (cloudflared isn't installed on the dev machine); the server, WebSocket flows and LAN address were.

## Static site (GitHub Pages)

`npm run build:site` (`scripts/build-site.js`) renders `views/jeu.ejs` with `page.js` data into **`docs/`** (committed, generated — never edit by hand) so the game can be served by GitHub Pages (Settings > Pages > branch `master`, folder `/docs`) at a stable URL, e.g. `https://neonix13.github.io/Village-Fantaisie/`. Asset URLs in `jeu.ejs`/`jeu.css` are deliberately **relative** (no leading `/`) so the site works under a sub-path. Re-run the build and commit `docs/` after every change to `public/`, `views/` or `roles.js`, otherwise the hosted copy goes stale. Pages needs HTTPS internet at first load; there is no service worker on `master` (it exists only on `appli-mobile`). The static build sets `window.VF_HOSTED = false`, so it always plays in local mode (one phone); only pages served by `server.js` (`VF_HOSTED = true`) connect to a shared game.

## Architecture

- **`public/game.js`** (browser + Node, no DOM) holds the rules and the **shared game** `G`: `phase` (`setup`→`pioche`→`hub`→`recap`), `count`, `custom`, `boxes`, `deck`, `players`, `pr`, `fee`, `spy`, `hl`, `winner`, `conv`, `rev`. `apply(G, action)` mutates `G` and returns `{ok, …}` or `{err}`; every change of the game goes through an action (`draw`, `kill-attempt`/`kill`, `pardon`, `vamp`, `priest-pick`, `fee-pick`, `spy-pick`, `reset-timer`, `custom-set`, `to-hub`, `end`, `new-game`…), validated server-side (own-property role checks, phase guards, atomic card draw so two phones can never get the same card). `view(G)` is what phones receive: **everything except `deck`**. `normalize()` also migrates the old single-object `vf-partie-v1` save (no `phase`, had `screen`).
- **`public/net.js`** has the two transports behind one interface (`start({onState,onStatus})`, `dispatch(action, cb)`, `now()`): `local` (applies `game.js` in the page, saves `G` in `localStorage` `vf-partie-v1`) and `ws` (WebSocket to `/ws` on the serving host, auto-reconnect with backoff, re-syncs when the phone wakes; `now()` is the host's clock so the Hérault timer agrees across phones). A future WebRTC transport (host = a phone) would implement the same interface.
- **`server.js`** (`createHost()`; also runnable directly) serves `GET /` (rendering `views/jeu.ejs`, `VF_HOSTED = true`), redirects `/jeu` → `/`, statics from `public/`, and the WebSocket `/ws`: one game per server, no rooms (whoever opens the address joins); each action is applied to `G`, the new state is broadcast to everyone *before* the result goes back to the sender. It also runs a heartbeat that drops dead sockets, a debounced snapshot to `partie.json` (gitignored) restored at startup, and the host-only pages `/hote`, `/hote/info`, `/hote/reset` (`views/hote.ejs`, QR codes as SVG via `qrcode`). `scripts/public.js` = server + cloudflared tunnel. `page.js` pre-renders every role badge once and injects `window.VF_ROLES`, `VF_PRIORITY`, `VF_BADGES`, `VF_HOSTED`.
- **`roles.js`** is the single source of truth for the role catalog (`ROLES`: camp, `known` for the public `***` roles, fixed `item`, `needsBox`, `special`, French description) and `PRIORITY` (the default pool of possible characters). Card copy is authored here with accents, matching the design handoff.
- **`views/partials/role_badge.ejs`** draws each role's SVG shield. Because the client has no template engine, `server.js` calls `ejs.render()` on it directly and ships the resulting strings; `badge(id, size, fill)` in `jeu.js` only injects width/height and a `--vf-badge-fill` CSS variable into the string.
- **`public/jeu.js`** is the UI: a hand-rolled `innerHTML` render loop, no framework. `state` merges the **shared game** (copied in by `onShared(view)` whenever a state arrives — never write shared fields directly: call `dispatch({type…}, cb)` and use the result in `cb`, e.g. `draw` returns the card index, `kill` returns the follow-up sheet) with **per-phone fields** (`screen`, `ob`, `tab`, `rview`, `space`, `cur`, `name`, `err`, `flipped`, `revealAt`) saved in `localStorage` `vf-ui-v1`. The game `phase` decides which screens a phone may show (`PHASE_SCREENS`): `syncScreen()` moves a phone when the phase changes under it, except a phone still reading its card (`reveal`) isn't yanked when the game starts. `refresh()` re-renders after a remote change but keeps focus and the typed name, and is skipped on the `deck`/`reveal` screens. On reload it deliberately downgrades `reveal`→`pioche`, `space`→`hub` and `deck`→`setup` for privacy. `render()` swaps `#vf-screen`; the bottom sheet (`#vf-sheet`), the connection banner (`#vf-link`) and the privacy curtain (`#vf-curtain`) live outside it so they survive re-renders and their animations don't restart. Screens: onboard → setup → (deck) → pioche → reveal → hub (Village / Espaces / Rôles tabs) → space → recap. Interactions are all `data-action`/`data-arg` attributes handled by one delegated `onClick` switch.
- **`public/jeu.css`** holds all styling (gold/tarot theme, design tokens as `--vf-*`, keyframes `vf*`). Most screen-specific layout is inline style strings inside `jeu.js`, copied from the design handoff.

### Game rules implemented in `game.js`

- **Deck = a pool, not a fixed list.** `state.custom` is a `{roleId: count}` pool of *possible* characters (default `countsOf(PRIORITY)`); it may exceed the player count. `drawFromPool(pool, n)` shuffles it, takes `n` cards, pads with Villageois if the pool is short, then repairs dependencies (Soldat needs Roi, Diable needs Démon) by swapping a card. Nobody knows the exact composition — the Rôles tab therefore lists possible roles without quantities. Keep it that way.
- **Everything shared is visible to every phone** (all players' roles are in the page state, as before when any phone could open any space); only the card `deck` stays on the host. Anyone with the address joins the game (no PIN yet).
- **Box numbers**: the role's `needsBox` items live in a numbered box (Sorcière, and the Loup-garou whose box holds red stickers, `boxItems`). Number is manual per role (`state.boxes[roleId]`, set on the "Boîtes" tab of the deck screen) or, if empty, fixed by the role's rank among all `needsBox` roles in `ROLES` (Sorcière 1, Loup-garou 2) so boxes can be prepared in advance — it no longer depends on draw order.
- **Manche (round)**: ends when the Hérault rings the horn (timer reset) or a player is declared "gracié(e)". Both restart the 30-min timer, clear the Fée's protection (`state.fee`) and re-enable the Vampire's bite (`state.conv`). A death by "Pendu" does *not* end the round.
- **Eliminations** go through a cause picker (Dévoré/Brûlé/Asphyxié/Pendu/Empoisonné); a Fée-protected player survives once instead. Killing the Roi offers to ban all living Soldats (cause `bannissement`).
- **Vampire** converts one living player per round (not the Licorne) into `rejeton_vampire`, who discovers it via a banner in their space; converting a Fée clears `state.fee`.
- Roles with `special`: Prêtre (2 private consultations), Fée, Espion (6-guess notebook; 6 correct at the end wins alone), Diable (sees all roles), Chaman (`shaman_dead`: sees the name and role of every dead player, live), Hérault (timer). Only Roi, Hérault and Diable are `known` (***, with a fixed object). The Diable dies with the last Démon (`devilFollowsDemons`; a Fée protection is consumed instead). **Succube** (`succube_target`, `G.suc[succubaIdx] = {t: target, done}`): picks one target, locked while it is alive (a target that died or was banned can be replaced); she may end its life herself (cause `asphyxie`, Fée protection absorbs it), but only 20 minutes after picking the target (`SUC_DELAY_MS`, `e.at` = host clock; the button shows a countdown), after which `done` forbids any new target; the target sees a banner in their secret space. **Loup-garou** (`werewolf_devour`, `G.lg[idx] = {at}`): from his secret space he can devour one living player. The victim only really dies if she wears a red sticker the werewolf physically placed: a minute later every phone shows "X a été dévoré(e)" and asks "porte-t-elle la marque ?" (`G.ask` queue, action `lg-verdict`, first answer wins: yes = killed with cause `devore` — a Fée protection absorbs it —, no = stays alive; a banner on the Village tab reopens the question; `G.seq` is a never-decreasing id counter shared by `ask` and `ann`, kept across `new-game`). Cooldown: one devour every 40 minutes (`LG_DELAY_MS`, running from the attempt), the first one only 20 minutes after the game starts (`LG_FIRST_DELAY_MS`, `G.start` set once by `to-hub`; unlike `hl` it is not reset by a manche). **Delayed announcement**: deaths caused by a power (Loup-garou devour, Succube kill) are queued in `G.pend` (host-only, stripped by `view()`) and only take effect `PENDING_MS` = 1 minute later, so nobody can link the death to who just used a power; `tick(G)` (called every 0.5 s by `server.js`, every 1 s by the local transport, and before/after every action) resolves due entries (a Succube kill lands then, the Fée absorbing it; a devour instead pushes the question to `G.ask`), and a dead Roi with living Soldats sets `G.ann` so every phone offers the Soldat ban. The killer only sees "sera déclaré(e) mort(e) dans 1 minute". Manual deaths from the Village screen stay immediate. Not modelled: the Licorne's revenge — these are table-talk, not app logic.

## Future: the game creator's phone as host

The host is currently the laptop (`server.js`). The plan is to let the creator's phone host instead, still without a third-party game server: a WebRTC transport (host phone = hub, public STUN only for address discovery, connection exchanged by QR/code — may fail on strict mobile networks without TURN) running the same `game.js` in the host's browser, or an embedded server in the Capacitor app on `appli-mobile`. Keep new game logic inside `game.js` actions and keep UI code free of direct shared-state writes so that swap stays cheap.

## Gotchas

- **Fonts are self-hosted** (`public/fonts/material-symbols-rounded{,-fill}.woff2`, static instances, outline + filled), not loaded from Google Fonts — deliberate, for the offline constraint. Icon names must exist in that font. If re-fetching, get the woff2 URLs from `fonts.googleapis.com/css2?family=Material+Symbols+Rounded:opsz,wght,FILL,GRAD@24,400,0,0` (and `…,1,0` for the filled one) with a Chrome user-agent.
- **EJS tokenizer trap**: `role_badge.ejs` once had a literal `<%- include(...) %>` example inside a JS comment inside a `<% %>` block, which produces `Could not find matching close tag for "<%"` with no line number, because EJS scans raw text for `<%`/`%>` without understanding JS comments. Never write tag-shaped text in a comment inside a scriptlet.
- Design source of truth: the handoff `Mobile app design planning.zip` (gitignored, kept outside version control; README + `.dc.html` source + a standalone `prototype-jouable.html`). Its README lists exact copy, sizes and timings per screen; the deck-customization, cause-of-death, manual-box, Vampire, Soldat-ban and "gracié(e)" features were added afterwards and are *not* in it.
- `data.sqlite*` files may still exist on disk from the deleted multi-device version; they are unused and gitignored. Don't delete them without asking — they hold old party data.
- Multi-line shell heredocs of ~30KB+ fail (`ENAMETOOLONG`), and even ~8KB ones containing quotes sometimes break the Bash tool ("unexpected EOF"); write large patches to a scratch file with the Write tool and apply them with a small node script.
